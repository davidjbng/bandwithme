# Version control

- Keep `origin/main` as GitButler's target. Do each task on its own local GitButler branch so parallel work can stay applied in the shared workspace. Use `but` for all version-control operations.
- Commit only the task's files or hunks to its branch. Preserve other agents' uncommitted changes and branches. Do not push task branches or open pull requests.
- When the task is ready to publish, run `but pull` to update the workspace and linked worktrees, resolve conflicts while preserving all involved work, and run relevant checks. Then use `but land <task-branch> --yes` to land that branch directly on `origin/main`. Land a whole stack only when all its branches belong to the task.
- A land pushes `main` and may trigger the configured deployment workflows. Never land another task's branch without an explicit request.

# Agent setup and quality

- Read `docs/research/modernization-validation.md` for the setup audit, verification evidence and remaining operational gates.
- Read `GLOSSARY.md` for domain terms. Tracker, triage labels and Wayfinder operations live in `docs/agents/`.
- Use agent-device for device work; Argent skills are retired. Consult Impeccable for UI quality and the exact installed Expo SDK docs for native components.
- `pnpm check` runs Vite+ formatting, linting and native TypeScript/tsgo checks. `pnpm test` runs Vitest, including backend, script and UI tests. Metro remains the Expo bundler.
- Use `pnpm web:export` and `pnpm e2e:smoke` for self-contained release-web checks. Authenticated/dev E2E tests need an explicitly selected test backend; never deploy or reset production to run CI.
- Prefer `@expo/ui` controls and Keyboard Controller for forms. Native dependency changes require a rebuilt client and iOS/Android validation; web checks alone are insufficient. See `docs/research/tooling-modernization.md` for version coupling and graphics/animation APIs.

# Changesets and delivery

- Add a user-focused Changeset with `pnpm changeset` for every major feature and meaningful user-facing change; use the appropriate semantic version bump. Keep it with the feature's branch.
- Changelogs and app versions are generated by `pnpm version-packages`; do not hand-edit release history. `package.json` and `app.json` marketing versions must agree.
- Main pushes and PRs run checks. Deployment starts from a manually published GitHub release, through the dedicated EAS workflow. Read `docs/deployment/expo-eas-publishing.md`.
- Invoke `release-app` only when asked to prepare/publish a release, and `review-dependency-updates` for selected dependency PR maintenance. Neither runs automatically during implementation. Do not publish a release as part of finishing ordinary work.

# Authentication and private ideas

- This repo uses Convex Auth 2 components. Follow `docs/research/auth-v2-reset.md`; do not restore v1 providers, authTables or JWT key setup. The 2026-11-14 clean-start authorization applies to the named legacy test deployment, not to later user data.
- Ideas remain private in Convex. Do not enable automatic GitHub publication or autonomous implementation. Use `review-app-ideas` when the user requests feedback review, and obtain explicit approval for the exact sanitized content before any public issue is created.
- Voice capture must require local recognition, never persist/upload audio, and preserve text entry as the fallback. Maintain the iOS speech patch and its tests until upstream closes the locale fallback. See `docs/research/feedback-and-device-ai.md`.
