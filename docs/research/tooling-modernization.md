# Dependencies and quality tooling

Research date: 2026-11-14. Decision ticket: [Dependencies and quality tooling compatibility](https://github.com/davidjbng/bandwithme/issues/29).

## Decisions

- Expo remains on SDK 58.0.25: all installed Expo SDK packages already matched the current stable registry release. React Native remains 0.88.1. The user requested all current dependencies, including newer React 19.3.1, Gesture Handler 3.5.0, Keyboard Controller 1.23.0 and Worklets 0.13.1. Reanimated 4.7.1 supports React Native 0.86–0.88 and Worklets 0.13.x. These explicitly requested newer releases differ from Expo's recommended bundled matrix and require new development/native builds. Do not mistake a passing web check for native compatibility. Sources: [Expo 58 reference](https://docs.expo.dev/versions/v58.0.0/), [Expo dependency validation](https://docs.expo.dev/more/expo-cli/#configuring-dependency-validation), [Keyboard Controller](https://kirillzyusko.github.io/react-native-keyboard-controller/), npm package metadata queried live.
- Convex moves to 1.50.0 and Auth 2.0.0. Auth 2 is component-based and replaces the old providers; it has fewer login methods than v1. The user expressly chose a clean start for existing auth and test app data; root owns that implementation and reset procedure. `@auth/core` is removed. Sources: [Auth 2](https://docs.convex.dev/auth/convex-auth), [setup](https://docs.convex.dev/auth/convex-auth/getting-started), [migration status](https://docs.convex.dev/auth/convex-auth/migrating/from-convex-auth-v1).
- Vite+ 1.6.0 owns formatting, linting, Go-powered type checking and Vitest 5.1.0. Expo/Metro still owns app bundling. `pnpm check` runs Oxfmt + Oxlint + TypeScript Go checks via `typeAware`/`typeCheck`; `pnpm typecheck` selects the same Go check without formatting/lint. No old `@typescript/native-preview` snapshot is added. `vite` resolves to `@voidzero-dev/vite-plus-core`; direct Vitest is retained because existing tests and Convex guidance import it. Sources: [check](https://viteplus.dev/guide/check), [migration rules](https://viteplus.dev/guide/migrate-rules), [Vitest 5 migration](https://viteplus.dev/guide/vitest-v5).
- The existing lint categories/rules remain; the new optional unsafe-assertion rule is off alongside the existing explicit-any exemption, avoiding an unrelated app-wide cast rewrite. Type errors remain blocking. Formatting excludes vendored skills and generated Convex outputs. Lefthook checks only; it no longer formats all files or stages unrelated changes in the shared GitButler checkout.
- Skia uses the current `react-native-skia` package (3.10.1), not the old Shopify package name. Graphite brings Metal/Vulkan rendering and built-in Skottie/Lottie support. Skia is a graphics capability, not a general 3D scene engine; add WebGPU/Three only when a concrete feature needs it. Native builds are required; web canvas consumers must initialize CanvasKit via the documented web loader. No unused WASM files or demonstration graphics are added to production screens. Sources: [Skia installation](https://wcandillon.github.io/react-native-skia/docs/getting-started/installation/), [v3 migration](https://wcandillon.github.io/react-native-skia/docs/getting-started/migration/), [Skia source](https://github.com/wcandillon/react-native-skia).
- Ease 0.10.0 complements Reanimated: use native platform animations for simple declarative transitions and retain Reanimated for gestures/worklets. Existing native UI uses `@expo/ui`; new controls should reuse it with web fallbacks. Sources: [Ease](https://github.com/AppAndFlow/react-native-ease), [Expo UI](https://docs.expo.dev/versions/v58.0.0/sdk/ui/).
- Production forms use universal Expo UI buttons and Keyboard Controller scroll views, retaining React Native text fields for focus tracking. Keyboard Controller 1.23.0's Android `FocusedInputObserver` only observes `EditText`, while Expo UI inputs render Compose `BasicTextField`; its iOS observer also derives input geometry and React view tags from UIKit responders. Do not assume SwiftUI/Compose fields support automatic focused-input scrolling without device evidence. Sources: installed `react-native-keyboard-controller/android/src/main/java/com/reactnativekeyboardcontroller/listeners/FocusedInputObserver.kt` and `@expo/ui/src/universal/TextInput/index.android.tsx`, [keyboard-aware scroll view](https://kirillzyusko.github.io/react-native-keyboard-controller/docs/api/components/keyboard-aware-scroll-view).
- Dependabot uses one monthly multi-ecosystem group for npm and GitHub Actions, all version levels included. Security update grouping is separate and does not wait for the monthly version schedule. Skills are source snapshots rather than npm dependencies; update them via the skills workflow. Sources: [multi-ecosystem groups](https://docs.github.com/en/code-security/how-tos/secure-your-supply-chain/secure-your-dependencies/configuring-multi-ecosystem-updates), [options](https://docs.github.com/en/code-security/reference/supply-chain-security/dependabot-options-reference).

## Reproducible validation

- `pnpm install --frozen-lockfile` uses the pinned package manager.
- Node 24.15+ on the 24.x line or Node 26+ satisfies the current toolchain and jsdom runtime tests; CI uses Node 24.
- `pnpm check` and `pnpm test` cover source/types and Convex tests.
- `pnpm test:design-demo` retains reducer invariants under Vitest. Release-metadata tests also run in the Node Vitest project; Convex tests use the edge-runtime project. A scoped WASM loader compiles the real Argon2 bytes exactly as Convex does; see the [upstream Auth test config](https://github.com/convex/convex-auth/blob/main/vitest.config.ts).
- `pnpm web:export && pnpm e2e:smoke` serves the static export on a dedicated port, tests desktop/mobile browser viewports and blocks Convex requests. It covers accessible sign-in controls, hidden password entry, invalid recovery/verification deep links, and keeping the design prototype hidden in production exports. Additional `e2e/prototype.spec.ts` development-server tests cover attendance/reset, voting/search and setlist state/reordering; they intentionally stay out of production smoke because the prototype is development-only.
- Existing authenticated tests stay available via `pnpm e2e` against a configured test backend; smoke tests do not replace them.
- The explicitly invoked `review-dependency-updates` skill reviews, repairs, validates and merges a selected passing PR. It does not publish a release.

## Installation policy

The pnpm build allowlist retains existing esbuild/Lefthook/msgpackr entries. Optional DTrace tracing and protobufjs's version-scheme warning-only postinstall are explicitly disabled; neither is required for app runtime. Newly published release tooling/browser packages have version-specific minimum-age exemptions emitted by pnpm during the requested latest-version upgrade. No global lifecycle-script allowance is enabled. Package-installed Ease skills are disabled because the reviewed skill is maintained in the repository's existing skill workflow.

## Verification results

See [integrated modernization validation](./modernization-validation.md) for the final combined checks, native compilation evidence and remaining verification gaps after all parallel changes.

At the tooling checkpoint, frozen lockfile installation passed and integrated Vitest runs passed 37 tests across eight files, including real Auth 2 password hashing and ten React DOM speech-input lifecycle tests. Vite+ lint and Go-powered type checking pass without warnings across 91 files. Expo web export passes. All eight production smoke cases and all six development-prototype browser cases pass across desktop and mobile Chrome viewports. The temporary development server was stopped afterward. Dependabot configuration passes its published JSON schema; the manual skill's YAML metadata and explicit-invocation policy validate.

Subsequent native build/device and deployment verification is recorded in the integrated report above. Expo Doctor passes 18 of 20 checks and flags the five newer native/React package versions above and the locally pinned EAS CLI. The EAS CLI pin is deliberate: CI uses a reproducible reviewed version and Dependabot can update it. No version mismatches are silently suppressed. Authenticated backend browser flows still require a configured disposable deployment; the isolated browser cases do not claim that coverage.
